Resize Images for a Faster Website

Unoptimised images are the single biggest cause of slow-loading web pages. A phone photo straight off a camera can be 4–8MB; the same image, sized and compressed properly, is often under 150KB with no visible quality loss at typical display sizes. That difference is most of what page-speed tools are measuring when they flag "properly size images" or "serve images in next-gen formats."

The two settings that matter

  • Pixel dimensions. Don't upload a 4000px-wide photo to display in a 800px-wide content column — resize to roughly the largest size it will ever actually display at (accounting for retina displays, maybe 1.5–2× that).
  • File format. WebP typically beats JPG by 25–35% at equivalent quality, which is exactly what "next-gen format" recommendations are asking for. See the full format comparison.

Practical workflow

  1. Decide your image's maximum display width on the page (check your site's CSS or theme if unsure — 1200–1600px covers most full-width blog images).
  2. Open the resizer, switch to Pixels mode, and set that width with aspect ratio locked.
  3. Set an optional max size — 150–300KB is a reasonable target for a full-width hero image; under 100KB for smaller inline images.
  4. Set Output format to WebP if your site/CMS supports it (nearly all modern ones do), otherwise JPEG.

Batch-processing a whole gallery

Got a folder of product photos or blog images to prep at once? The bulk resize guide covers dropping a whole batch in with one width setting and downloading everything as a ZIP.

A resized, well-compressed image set is the highest-leverage, lowest-effort page-speed fix most sites can make — it usually beats server-side caching tweaks for perceived load time, and takes minutes rather than a development sprint.
